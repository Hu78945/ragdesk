Kestrel REST API Reference

The REST API is served under the /api/v1 prefix on the same port as the dashboard. All requests must send an Authorization: Bearer <token> header. Responses are JSON.

Jobs

GET /api/v1/jobs lists all jobs with their schedule, queue, and paused state.

POST /api/v1/jobs/{name}/trigger starts a run immediately, ignoring the schedule. It requires the operator role and returns the new run ID with status 202.

POST /api/v1/jobs/{name}/pause and POST /api/v1/jobs/{name}/resume pause and resume the schedule.

Runs

GET /api/v1/runs?job={name}&status={status} lists runs, newest first. Valid statuses are queued, running, succeeded, failed, and dead_lettered.

GET /api/v1/runs/{id}/logs streams the run's log output as server-sent events while the run is active.

POST /api/v1/runs/{id}/cancel cancels a queued or running run. Running commands receive SIGTERM, then SIGKILL after a 30 second grace period.

Pagination

List endpoints use cursor pagination. Pass the next_cursor value from a response as the cursor query parameter. The default page size is 50 and the maximum is 500.

Rate limits

Each token may make 600 requests per minute. Exceeding the limit returns HTTP 429 with a Retry-After header.

Errors

Errors use the shape {"error": {"code": "KST-1001", "message": "..."}}. KST-1001 means the job was not found, KST-2003 means the token lacks the required role, and KST-4102 means the worker running the job was lost.
